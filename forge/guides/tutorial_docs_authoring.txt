# tutorial-docs-authoring

## SUMMARY
Learn how to write Forge living docs: short pages with inline links, copyable bundles, and clear expected packet output.

## WHEN TO USE
Use this when you want to create or improve docs for Forge, LinkOS, tutorials, onboarding, or workflow guidance.

## GOAL
Learn how docs work as action surfaces.

A Forge living doc can contain:
- short human-readable explanation
- inline links to other docs
- copyable Forge bundles
- expected packet output
- next-step links

## CORE SYNTAX
Use inline doc links like this:

    Read [[tutorial-loop]] before [[tutorial-patching]].

Use copyable bundle blocks like this:

    @forge-bundle example-name
    LIST_FILES .
    DEPTH: 2
    FILES: no
    @end-forge-bundle

LinkOS renders that bundle as a copyable object.

## STEP 1 — READ THE DOCS HELP
Start by reading the canonical reference.

    @forge-bundle tutorial-docs-help
    HELP DOCS

    HELP GUIDE

    DOCS
    SUGGEST: docs-authoring, tutorial, tutorial-loop
    @end-forge-bundle

## EXPECT
The packet should show:
- DOCS syntax
- GUIDE syntax
- living-doc rules
- @forge-bundle notation

## STEP 2 — CREATE A TINY DOC
This creates a harmless tutorial doc in the guides folder.

    @forge-bundle tutorial-docs-create
    CREATE_FILE forge/guides/tutorial_scratch_doc.txt
    BEGIN_BODY
    # tutorial-scratch-doc

    ## SUMMARY
    A tiny scratch doc for learning Forge living docs.

    ## WHEN TO USE
    Use this only as a tutorial example.

    ## TRY THIS
    This is a read-only starter bundle.

        @forge-bundle scratch-doc-read-only
        LIST_FILES scratch
        DEPTH: 2
        FILES: no
        @end-forge-bundle

    ## NEXT
    Read [[tutorial-docs-authoring]] when finished.
    END_BODY

    DOCS
    OPEN: tutorial-scratch-doc
    SUGGEST: tutorial-docs-authoring
    @end-forge-bundle

## EXPECT
The packet should show:
- CREATE_FILE applied
- DOCS opened the new doc
- the doc renders with a Copy bundle object

## STEP 3 — OPEN THE DOC AGAIN
Use DOCS OPEN to render a doc in the packet.

    @forge-bundle tutorial-docs-open
    DOCS
    OPEN: tutorial-scratch-doc
    SUGGEST: tutorial-docs-authoring, tutorial
    @end-forge-bundle

## EXPECT
The packet should render the doc inline.

In LinkOS, the doc should have:
- Copy doc
- inline links
- Copy bundle object

## STEP 4 — CLEAN UP
Remove the scratch tutorial doc when done.

    @forge-bundle tutorial-docs-cleanup
    DELETE_FILE forge/guides/tutorial_scratch_doc.txt
    @end-forge-bundle

## EXPECT
The packet should show:

    APPLIED | DELETE_FILE | forge/guides/tutorial_scratch_doc.txt

## WRITING RULES
Keep docs:
- short
- human-first
- linked to related pages
- focused on one workflow
- built around small safe bundles
- clear about expected packet output

Do not make huge docs. Split long tutorials into smaller docs.

## WHEN TO UPDATE HELP
If a doc explains op behaviour, ask:

    Should this be in HELP <OP> instead?

Examples:
- DOCS syntax belongs in HELP DOCS
- GUIDE behaviour belongs in HELP GUIDE
- recovery workflow belongs in a tutorial or guide

## COMMON MISTAKES
- Writing model-only prose into human docs.
- Making one doc too long.
- Using markdown triple-backtick fences for Forge bundles.
- Forgetting expected packet output.
- Adding copyable bundles that are too risky for beginners.
- Forgetting to link the next step.

You learned how to create a living doc that can explain, link, and contain runnable Forge bundles.
