# run-packet

## WHEN TO USE
Use when the user asks what a packet means, or when teaching how to read Forge output.

## SUMMARY
The run packet is Forge's report. It tells you what was attempted, what succeeded, what was skipped, what failed, and what the ops produced.

## STRUCTURE

    === FORGE2 RUN ===
    Run: 20260502_141432

    Ops:
    - APPLIED | LIST_FILES | . :: 76 entries
    - APPLIED | PREVIEW    | some/file.py :: 40 lines
    - SKIPPED_ANCHOR_MISMATCH | REPLACE_LINE | other/file.py :: matched 0 times

    APPLIED=2  SKIPPED=1  FAILED=0

    === PREVIEW ===
    [actual output of each op]

## STATUS CODES
APPLIED
    The op ran and made the change it was supposed to make.

SKIPPED_ALREADY_APPLIED
    The file already matches the requested state. Safe — no action needed.

SKIPPED_ALREADY_PRESENT
    An insert was attempted but the inserted def already exists. Safe.

SKIPPED_ANCHOR_MISMATCH
    An anchor matched zero times or more times than expected. The op did not run. Tighten the anchor and retry.

FAILED_NOT_FOUND
    The target class, function, method, or file was not found. Check the path and target syntax.

FAILED_AMBIGUOUS
    The target name matched more than one thing. PREVIEW or LIST_TARGETS to disambiguate.

FAILED_PARSE
    The bundle directive was malformed. Run HELP <OP> before retrying.

FAILED_IO
    File not found, or path escaped project root.

FAILED_COMPILE
    A patch was applied but the resulting file failed compile(). Forge automatically rolled the file back. Fix the syntax and retry.

## READING ORDER
1. Check the summary line first. If FAILED > 0, address those before anything else.
2. Read each op line in order. Earlier ops in a bundle may have changed the file before later ops ran.
3. Read the PREVIEW section for actual content (file listings, search hits, file slices, run output).

## RULE
The packet is the source of truth. Never claim a file changed unless the packet shows APPLIED for that op.
