# strava

## WHEN TO USE

Use this guide when working on Jack's Strava integration, training import system, training journal sync, Strava cache/library, or the daily `strava-sync` workflow.

This guide is for both:
- human daily use after uploading a session to Strava
- LLM/Forge maintenance work on the Strava tooling

## GOAL

The goal is simple:

Jack finishes a training session, updates Strava, then runs one command.

That command should:
1. refresh Strava token if needed
2. fetch recent Strava activities
3. fetch detailed activity data including Strava notes/descriptions
4. merge into the local Strava library without duplicates
5. write missing clean training entries into the journal
6. repair existing Strava journal entries if notes were fetched later
7. avoid duplicate journal entries using `strava_id`

Normal daily command:

    strava-sync

Or directly:

    STRAVA
    ARGS: update
    TIMEOUT: 180

## WHAT UPDATE DOES

`STRAVA update` is the one-command maintenance flow.

It runs:

1. `sync [days] [detail_cap]`
   - fetches recent Strava activities
   - refreshes token as needed
   - fetches detailed activity records
   - captures Strava notes/descriptions
   - merges into local library by `strava_id`

2. `sync-journal [days] --write`
   - reads from the local library
   - groups activities by training day
   - writes missing journal entries
   - skips activities whose `strava_id` is already present

3. `repair-journal-notes [days] --write`
   - updates existing Strava journal entries from enriched cache
   - adds notes/descriptions when they were fetched after the original journal import
   - does not create duplicate entries

## IMPORTANT GUARANTEE

The system is designed to be safe to re-run.

Library duplicate prevention:
- activities are merged by `strava_id`

Journal duplicate prevention:
- daily journal entries include `strava_id:` and `strava_ids:` markers
- `sync-journal` checks existing day files before writing
- existing IDs are skipped

Repair behaviour:
- `repair-journal-notes` updates existing Strava journal entries
- it does not create new journal entries

## LOCAL LIBRARY

`library/strava/activities_raw.json` is the source of truth for imported Strava activities.

It stores normalized activity records, including:
- `strava_id`
- name/title
- sport type
- start date/local date
- distance miles
- moving time
- elapsed time
- elevation
- average/max heart rate
- pace or speed
- URL
- Strava notes/descriptions where available

`activities_summary.md` is human-readable.
It groups activities by month.

`sync_state.json` records the latest sync/archive operation.

## STRAVA NOTES

Bulk Strava activity fetch does not reliably include user notes/descriptions.

To capture notes, `sync` performs detail enrichment:
- fetch activity list
- fetch detail endpoint per recent activity
- copy description/notes into `strava_note` and `description`
- merge enriched record into the cache

This is why the normal command should be:

    STRAVA
    ARGS: update
    TIMEOUT: 180

or:

    strava-sync

Do not rely on historical archive alone for notes. Historical archive is mainly factual bulk data unless enriched later.

## JOURNAL ENTRY SHAPE

Daily imported entries are factual and structured.

Example shape:

    source: strava
    strava_ids: 18252008035, 18252016364
    activity_count: 2

## IMPORTANT DESIGN DECISION

The journal should not become a giant Strava clone.

Detailed historical data lives in:

    library/strava/activities_raw.json

The journal should contain:
- recent day-level training entries
- useful factual daily summaries
- one or more higher-level historical summaries if needed
- coaching interpretation separately, not during import

The Strava import layer should remain factual.

## TOKEN MANAGEMENT

Status command:

    STRAVA
    ARGS: status

Token file:

    .forge_secrets/strava_token.json

The CLI refreshes tokens when needed. Normal `sync` / `update` should keep access alive as long as:
- client ID/secret are valid
- refresh token is valid
- Strava app permissions are not revoked

If auth fails:
1. run status
2. generate auth URL if needed
3. exchange returned localhost URL/code
4. save refreshed token back into `.forge_secrets`

Do not print full tokens or client secrets in chat or guides.

## PACK SAFETY

Do not pack secrets.

PACK should exclude:
- `.forge_secrets/`
- API keys
- tokens
- credential files
- `library/keys/` if it contains secrets

The upgraded PACK op warns on secret-looking files, but still treat secret exclusion as mandatory.

## TROUBLESHOOTING

Problem: update times out
- increase TIMEOUT
- use smaller window, e.g. update 7 30

Problem: notes missing
- run sync/update again with enough detail cap
- then run repair-journal-notes

Problem: duplicate journal entries
- inspect day JSON
- check whether `strava_id` markers are present
- duplicate-proofing depends on those markers

Problem: library has data but journal search does not show it
- journal JSON has likely been written correctly
- index refresh may not yet be wired
- inspect journal day file directly
- later fix: wire proper journal index rebuild

Problem: credentials missing
- inspect `.forge_secrets/strava_token.json`
- inspect `library/keys/` only if using temporary staging
- do not expose keys in chat

Problem: Strava status says ready for auth/exchange even after auth
- wording may be stale/misleading
- token presence is the key fact
