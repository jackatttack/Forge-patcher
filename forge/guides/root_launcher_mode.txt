# root-launcher-mode

## SUMMARY
Forge has an active project root. Contained mode keeps Forge inside its own folder. Root launcher mode gives Forge access to the wider Pythonista Documents workspace.

## WHEN TO USE
Use this when a user wants Forge to work across their whole Pythonista workspace instead of only the folder where Forge was installed.

## ACTIVE PROJECT ROOT
Forge always runs against one active project root.

The LLM must not guess the scope.

It should run:

    LIST_FILES .
    DEPTH: 2
    FILES: no

Then infer the active root from the packet.

If the packet only shows the Forge install folder, the user is in contained mode.

If the packet shows the broader Pythonista workspace, the user is in root launcher mode.

## CONTAINED MODE
Contained mode is the safest first setup.

In this mode:

- forge_entry.py lives inside the Forge install folder
- linkos.py lives beside forge_entry.py
- Forge can inspect and patch that folder
- tutorials and first runs stay contained

This is best for onboarding, experiments, and cautious first use.

## ROOT LAUNCHER MODE
Root launcher mode is more powerful.

In this mode:

- launcher files live at Pythonista Documents root
- Forge can inspect and patch the wider workspace
- project folders, tools, scratch files, and apps become visible from LIST_FILES .

This should be deliberate. Do not surprise the user by expanding scope.

## HOW TO GIVE FORGE ROOT ACCESS
Use or create an installer/promotion script that places launchers at Pythonista Documents root:

    forge_entry.py
    linkos.py

The launchers should still import the Forge package from the installed Forge folder or from the root package, depending on the user's setup.

After installing root launchers, run the first safe bundle again and check the packet.

## RULE FOR AI ASSISTANTS
Never assume Forge can see the whole device or the whole Pythonista workspace.

The packet decides.

If the user asks why Forge cannot see their files, explain contained mode and root launcher mode. Offer to inspect the current root with LIST_FILES before suggesting changes.
