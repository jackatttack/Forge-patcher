# training

## WHEN TO USE

Use this guide when helping Jack with endurance training, training planning, injury-aware coaching, Strava-derived analysis, or weekly plan decisions.

This guide explains how to use the local training intelligence stack:

- STRAVA imports factual activity data.
- TRAINING analyses the activity library.
- JOURNAL stores subjective notes, plans, decisions, and training context.

## PRODUCT ROLES

### STRAVA

Factual import layer.

Use it to:
- refresh token
- fetch recent activities
- enrich activity notes/descriptions
- merge activities into `library/strava/activities_raw.json`
- write factual daily training entries into Journal
- avoid duplicates using Strava IDs

Main command:

    STRAVA
    ARGS: update 14
    TIMEOUT: 180

Historical archive:

    STRAVA
    ARGS: archive-all 10 50
    TIMEOUT: 300

## HOW TO COACH JACK

Jack is not a novice.

He has a high athletic ceiling and a serious training background. The main limiter is usually not aerobic potential; it is durability, sequencing, and avoiding recurring injury cycles.

Current default coaching principle:

    Build fitness pain-free first.
    Use intensity carefully.
    Do not let the long run dominate every week.
    Use the bike to support aerobic load.
    Heavy gym matters, but do not make hamstrings heroic.
    Prefer consistency over proving fitness.

## INTERPRETING FLAGS

TRAINING flags are context, not verdicts.

Important flags:
- `RUN_LOAD_SPIKE`
- `RETURN_TO_RUN_SPIKE`
- `RUN_FREQUENCY_JUMP`
- `RUN_INTENSITY_STACK`
- `LONG_RUN_DOMINANCE`
- `INJURY_NOTE`
- `GPS_WEIRDNESS`

Do not assume a flagged week failed.

A successful block can include intensity spikes.

The useful distinction:

    productive stress =
    intensity inside an otherwise controlled block

    risky stack =
    load jump + long-run dominance + high hard density + injury-note context

Use flags to decide what to inspect.

## HISTORICAL READ SO FAR

The data shows two broad templates.

### High-capacity template

Jack has historical blocks around:
- 25–32 miles/week
- 5–7 runs/week
- 3–4 hard-ish touches/week

These prove capacity.

They are not automatically the right template now because some carry intensity-stack, load-spike, GPS, or injury-note context.

### Current rebuild template

More useful for current planning:
- roughly 10–20 miles/week
- 3–4 run days
- one longer run
- one controlled quality exposure
- bike support restored when run load rises
- gym/rehab maintained

This is the safer template to copy during rebuild.

## CURRENT COACHING READ

The recurring pattern:

    Jack is aerobically ahead of his musculoskeletal tolerance.

This is good, but it means planning needs discipline.

Do not be timid.
Do not be reckless.

Use bike and gym to support the build.
Keep running consistent.
Ration the “I’m fitter than I thought” sessions.

## PLANNING RULES

Only increase one stressor at a time:

- run mileage
- run frequency
- long run
- hard run density
- gym load
- physically demanding work load

If recent run load has jumped sharply, consolidate before building.

If long run is more than around 40% of weekly run mileage, do not push the long run again unless the rest of the week is deliberately easier.

If bike support has dropped while run load rises, restore bike support rather than adding more run miles.

If hard-ish density is already high, the next hard session must be earned.

## GOOD WEEK SHAPE DURING REBUILD

Default structure:

- 3–4 runs
- 1 long/easy run
- 1 controlled quality touch
- 1–2 bike sessions
- 1–2 gym sessions
- rehab/mobility as support
- easy days genuinely easy

Example:

    Mon — bike aerobic/recovery + rehab
    Tue — easy run 30–40 min
    Wed — bike threshold/support
    Thu — controlled run quality
    Fri — gym + optional easy spin/walk
    Sat — long easy/social run
    Sun — easy shakeout or bike depending on hamstring

## WHAT QUESTIONS TO ASK

Before planning, ask only useful questions.

Good questions:
- How is the hamstring today?
- Any Achilles noise?
- How much Ropehawn/manual load is expected this week?
- How much sleep/stress disruption?
- Did the last long run leave soreness?
- Are we protecting consistency or deliberately pushing one stressor?
- Is the bike available this week?
- Is gym realistic this week?

Avoid asking broad questions if the data already answers them.

## HOW TO USE PERFORMANCE SIGNALS

Performance signals show capacity.

They should answer:
- What paces have recently been possible?
- Which fast sessions were tolerated?
- Which long runs carried high HR?
- What controlled aerobic pace/HR markers exist?

Do not turn every good performance signal into a plan.

Use performance signals to set confidence, not ego.

## HOW TO USE DURABILITY SIGNALS

Durability signals ask:

    What happened after the stress?

Good follow-up running suggests the session was absorbed.

Injury-note follow-up means inspect context.

Hard-stacked follow-up may be okay, but it is where risk hides.

Use durability signals before copying historical sessions.

## STOP CONDITIONS

Stop and ask Jack before planning aggressively if:
- hamstring pain is rising
- Achilles pain returns
- recent journal notes mention flare-up
- Strava data has GPS weirdness around the key session
- manual work/Ropehawn load is unusually high
- the plan would increase multiple stressors at once
- the data and subjective context disagree
