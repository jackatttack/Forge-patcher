# debug-crash

## WHEN TO USE
Use when Pythonista shows a traceback, an app crashes, an op fails unexpectedly, or Forge itself appears broken.

## PATTERN
1. Read the traceback literally.
2. Identify file, line, function, and error type.
3. PREVIEW around the failing line.
4. LIST_TARGETS the Python file if patching.
5. Patch the smallest reliable target.
6. RUN_FILE the crashed entry point or a small probe.
7. If Forge core is broken, restore from branch.

## GOOD FIRST MOVES
- PREVIEW the traceback file around the reported line.
- LIST_TARGETS the traceback file if it is Python.
- GREP for the failing symbol or error string.
- HELP the patch op before retrying if the first patch failed.

## VALIDATE / SMOKE TEST
- For Forge core: RUN_FILE forge/entry.py
- For an op: REFRESH, then HELP or direct op test
- For UI: launch the app and ask Jack for the visible result
- For CLI: RUN_FILE the CLI with a small command

## COMMON FAILURES
- IndentationError: PREVIEW around the line and consider replacing the whole enclosing function.
- SyntaxError after line-range patch: use REPLACE on the enclosing target.
- AttributeError on None: inspect initialisation and caller flow.
- ImportError after a new op/file: REFRESH or restart Pythonista if needed.
- sys.exit in Pythonista threaded RUN_FILE can appear as KeyboardInterrupt; avoid sys.exit in testable op modules.
