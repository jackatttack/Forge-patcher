# tutorial-ops

## SUMMARY
Learn the main Forge op families and how to choose the right op for a task.

## WHEN TO USE
Use this after [[tutorial-patching]] when you want a guided map of common Forge capabilities.

## GOAL
Forge ops fall into families:

- inspect
- file write
- AST write
- file manage
- run and recovery
- docs and guidance
- custom tools

You do not need to memorise every op. Learn how to discover and inspect them.

## STEP 1 — LIST CORE OPS
Start with the everyday op vocabulary.

    @forge-bundle tutorial-ops-core
    LIST_OPS core

    DOCS
    SUGGEST: concepts, run-packet, safe-patch
    @end-forge-bundle

## EXPECT
The packet should group core ops by category.

Look for:
- Inspect
- AST write
- File write
- File manage
- Run / automation
- Meta

## STEP 2 — LIST CUSTOM OPS
Custom ops expose user-specific tools and higher-level workflows.

    @forge-bundle tutorial-ops-custom
    LIST_OPS custom
    DOCS
    SUGGEST: docs-vs-guide, tutorial-extension
    @end-forge-bundle

## EXPECT
The packet should show tools like DOCS, JOURNAL, PDF, LINKOS, TRAINING, STRAVA, and others if available.

## STEP 3 — READ HELP FOR AN OP
HELP is the source of exact syntax.

    @forge-bundle tutorial-ops-help
    HELP PREVIEW

    HELP REPLACE_FILE

    HELP BRANCH

    HELP DOCS
    @end-forge-bundle

## EXPECT
The packet should show:
- required directives
- optional directives
- body rules
- common failures
- examples

Use HELP before unfamiliar ops and always after FAILED_PARSE.

## STEP 4 — INSPECT OPS BY FAMILY
This bundle opens docs that explain the safest working patterns.

    @forge-bundle tutorial-ops-patterns
    DOCS
    OPEN: inspect-first, safe-patch, run-packet
    SUGGEST: tutorial-search, tutorial-patching
    @end-forge-bundle

## OP FAMILY MAP
Inspect ops help you understand what exists:

- LIST_FILES
- GREP
- PREVIEW
- READ_FILE
- LIST_TARGETS
- HELP
- LIST_OPS

File write ops change plain text files:

- CREATE_FILE
- REPLACE_FILE
- REPLACE_FILE_RANGE
- REPLACE_BLOCK
- INSERT_FILE_LINE

AST write ops change Python structure:

- REPLACE
- INSERT_AFTER
- INSERT_BEFORE
- INSERT_INTO
- APPEND_INTO
- PREPEND_INTO
- REPLACE_LINES
- REPLACE_LINE

File manage ops move or delete things:

- MOVE_FILE
- COPY_FILE
- DELETE_FILE
- MOVE_DIR
- DELETE_DIR

Run and recovery ops help verify or undo work:

- RUN_FILE
- BRANCH
- LIST_RUNS
- DIFF
- REVERT_RUN
- REFRESH

Docs and guidance ops help you learn and preserve workflow knowledge:

- HELP
- GUIDE
- DOCS
- JOURNAL

## CHOOSING AN OP
Use this rough rule:

- Need to find something? Use GREP.
- Need to read code? Use PREVIEW.
- Need exact syntax? Use HELP.
- Need to create a new file? Use CREATE_FILE.
- Need to rewrite a small whole file? Use REPLACE_FILE.
- Need to edit one Python function? Use REPLACE.
- Need to edit part of a Python function? Use REPLACE_LINES.
- Need to branch before risk? Use BRANCH.
- Need to prove code works? Use RUN_FILE.
- Need to recover? Use BRANCH restore or REVERT_RUN.
- Need to show docs? Use DOCS.

## COMMON MISTAKES
- Using a write op before inspecting.
- Guessing directives instead of using HELP.
- Using REPLACE_FILE on a large file when a smaller patch would do.
- Forgetting that AST ops require Python files that currently parse.
- Forgetting that failed or skipped ops are not successful edits.
