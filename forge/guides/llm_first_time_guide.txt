# llm-first-time-guide

## SUMMARY
Instructions for an LLM assistant using Forge for the first time.

## WHEN TO USE
Use this when a new user presses Start in LinkOS and pastes the copied guide into an LLM.

## CORE IDEA
Forge is a clipboard-based patching harness for Pythonista on iOS.

The loop is:

1. The assistant writes a plain-text Forge bundle.
2. The user copies that bundle to the clipboard.
3. The user runs forge_entry.py in Pythonista.
4. Forge executes locally.
5. Forge writes a run packet back to the clipboard.
6. The user pastes that packet back to the assistant.

The run packet is the source of truth.

Do not claim a file was changed, moved, deleted, uploaded, or tested unless the packet confirms it.

## TWO SURFACES
Forge has two important surfaces:

- The run packet is for the assistant. It is copied back to the clipboard.
- LinkOS is for the user. forge_entry.py renders LinkOS after every run as the final console surface.

Do not put LINKOS in the first boot bundle unless the user specifically asks. The entrypoint handles the post-run LinkOS surface.

## ACTIVE PROJECT ROOT
Forge always runs against one active project root.

Contained mode means Forge is running inside its own install folder. Root launcher mode means Forge launchers live at Pythonista Documents root and can work across the wider Pythonista workspace.

Do not assume scope. Use LIST_FILES . and the packet to infer what Forge can currently see. If the user wants broader access, explain root launcher mode.
## WHAT A RUNNABLE BUNDLE LOOKS LIKE
A runnable Forge bundle is plain text.

Each op starts with an op line. Optional directive lines follow it.

Example runnable bundle:

    LIST_FILES .
    DEPTH: 2
    FILES: yes

    LIST_OPS

    HELP DOCS

The user should copy only the runnable bundle text into Forge.

## DOC EXAMPLE BLOCKS ARE DIFFERENT
Forge docs may show copyable lesson bundles using markers like this:

    @forge-bundle example-name
    LIST_FILES .
    DEPTH: 2
    FILES: no
    @end-forge-bundle

Those wrapper lines are documentation metadata.

They are not part of the runnable bundle you should output in chat.

When chatting with the user, output only the runnable bundle contents inside a normal code block.

## YOUR FIRST RESPONSE
Give the user one short instruction, then output exactly this runnable bundle in a code block:

    LIST_FILES .
    DEPTH: 2
    FILES: yes

    LIST_OPS

    DOCS
    OPEN: onboarding
    SUGGEST: concepts, the-loop, run-packet, tutorial-loop, inspect-first, safe-patch

    HELP DOCS

    HELP LINKOS

    HELP LIST_FILES

    HELP CREATE_FILE

    HELP RUN_FILE

Do not include @forge-bundle wrappers.

Do not improvise a larger first bundle.

## AFTER THE FIRST PACKET
Read the packet carefully.

You should have:

- the project file tree
- the available ops
- onboarding docs rendered or suggested
- a LinkOS run surface rendered after the packet

Then say something like:

Good — you have completed the first Forge loop. The packet is the source of truth. LinkOS and the docs are now available, so we can either learn Forge step by step or start working directly.

## OPERATING RULES
- Inspect before editing.
- Keep bundles small.
- Wait for packets.
- Correct mistakes from packets instead of guessing.
- Use HELP before unfamiliar ops.
- Use DOCS for onboarding and workflow guidance.
- Use BRANCH before risky or core edits.
- Prefer scratch/ for tutorials and experiments.
- Never ask the user to paste secrets into chat.
