# tutorial

## WHEN TO USE
Use when the user is new to Forge and wants a hands-on walkthrough.
The lessons run in scratch/forge_tutorial/ so nothing real is at risk.

## TEACHING CONTRACT
This guide contains SIX lessons. Each lesson has its own bundle.

You will:
1. Read ONE lesson from this guide.
2. Explain it in plain language (2-3 sentences).
3. Send ONLY that lesson's bundle.
4. Wait for the packet.
5. Read the packet and summarise what happened.
6. Ask if the user wants to continue.

You will NOT:
- Send multiple lessons in one bundle.
- Combine lesson bundles to "save time."
- Skip the wait-for-packet step.
- Move on without the user's nod.

If the user says "skip the explanations" or "just run them all," you may
batch lessons. Otherwise: one at a time.

For the full teaching playbook see GUIDE teaching_style.

## SETUP CONTEXT (for the AI, not the user)
The tutorial uses scratch/forge_tutorial/ as a sandbox. CREATE_FILE will
create the directory automatically. No setup bundle is needed before
Lesson 1.

================================================================
LESSON 1 — INSPECT
================================================================
GOAL: See what's in the project. Forge always starts with discovery.

EXPLAIN: LIST_FILES gives a tree view of the repo from a chosen depth.
DEPTH: 2 means top-level dirs and their immediate children. FILES: yes
includes file names. Without it, you only see directories.

BUNDLE:

    LIST_FILES .
    DEPTH: 2
    FILES: yes

EXPECT: A tree of directories and files in the PREVIEW section, ending
with a count like "76 entries". Status APPLIED.

WAIT FOR PACKET. Then ask the user if they want to continue.

================================================================
LESSON 2 — CREATE
================================================================
GOAL: Make a file from a Forge bundle.

EXPLAIN: CREATE_FILE writes a new file. The path is relative to project
root. BEGIN_BODY / END_BODY wrap the file's contents. Forge creates any
missing parent directories — that's why scratch/forge_tutorial/ doesn't
need to exist first.

BUNDLE:

    CREATE_FILE scratch/forge_tutorial/hello.py
    BEGIN_BODY
    print("Hello from Forge")
    END_BODY

EXPECT: Status APPLIED. The packet will say "Created:
scratch/forge_tutorial/hello.py".

WAIT FOR PACKET. Then ask the user if they want to continue.

================================================================
LESSON 3 — RUN
================================================================
GOAL: Execute a Python file and read its output.

EXPLAIN: RUN_FILE runs a Python file inside Pythonista and captures
stdout, stderr, and the exit code. The output appears in the packet's
PREVIEW section. This is how Forge confirms code does what you think it
does — by running it.

BUNDLE:

    RUN_FILE scratch/forge_tutorial/hello.py

EXPECT: Status APPLIED. The PREVIEW section shows "exit 0" and the
captured stdout: "Hello from Forge".

WAIT FOR PACKET. Then ask the user if they want to continue.

================================================================
LESSON 4 — PREVIEW
================================================================
GOAL: Read a file's content without running it.

EXPLAIN: PREVIEW shows numbered lines from a file. LINES: 1-20 limits
the slice. PREVIEW is the safe way to read code before patching it —
the AI uses this constantly to check what's actually on disk.

BUNDLE:

    PREVIEW scratch/forge_tutorial/hello.py
    LINES: 1-20

EXPECT: Status APPLIED. The PREVIEW section shows the file's lines
prefixed with line numbers.

WAIT FOR PACKET. Then ask the user if they want to continue.

================================================================
LESSON 5 — PATCH
================================================================
GOAL: Replace a file's contents with new text.

EXPLAIN: REPLACE_FILE rewrites a whole file. The new content goes in
the body. Use this for small files and total rewrites. For surgical
edits inside large files there are smarter ops — REPLACE_LINE,
REPLACE_LINES, and the AST ops — but those come later.

BUNDLE:

    REPLACE_FILE scratch/forge_tutorial/hello.py
    BEGIN_BODY
    name = "Forge user"
    print("Hello, " + name)
    END_BODY

EXPECT: Status APPLIED. The file is now two lines.

OPTIONAL FOLLOWUP: Suggest the user might want to RUN_FILE again to
confirm the new behaviour. If they say yes, send a single RUN_FILE
bundle as Lesson 5b. Do not chain it onto this lesson.

WAIT FOR PACKET. Then ask the user if they want to continue.

================================================================
LESSON 6 — CLEAN UP
================================================================
GOAL: Move and delete files. Leave the sandbox tidy.

EXPLAIN: MOVE_FILE renames or relocates a file. DEST: is the new path.
DELETE_FILE removes a file from disk. Both ops appear in run history,
so they can be reverted with REVERT_RUN if needed.

This is two ops in one lesson because they're a logical pair — rename,
then delete the renamed file. That's the only place in the tutorial
where one bundle does two things, and it's deliberate.

BUNDLE:

    MOVE_FILE scratch/forge_tutorial/hello.py
    DEST: scratch/forge_tutorial/greeting.py

    DELETE_FILE scratch/forge_tutorial/greeting.py

EXPECT: Two APPLIED lines in the packet. The file no longer exists.
The scratch/forge_tutorial/ directory remains (Forge does not auto-
remove empty parent dirs).

WAIT FOR PACKET. Then close the tutorial.

================================================================
END
================================================================

After Lesson 6, the user has touched: discovery, creation, execution,
inspection, patching, and cleanup. They've felt six clean Forge loops.
