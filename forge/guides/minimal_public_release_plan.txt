# minimal-public-release-plan

## SUMMARY
Plan the additions needed to turn workspaces/minimal_forge into a public Forge release with LinkOS, living docs, tutorials, and a clean first-user onboarding loop.

## CURRENT DISK TRUTH
Minimal Forge lives at:

    workspaces/minimal_forge/

It uses:

    forge/
    forge_entry.py

It does not use:

    forge/
    forge_entry.py

Current minimal Forge has:
- 39 core ops
- auto-discovered core/custom op layers
- HELP and HINTS across most ops
- GUIDE op
- 5 guides
- PIP
- URL
- run storage
- branch/diff/revert
- emergency_revert.py

It does not yet have:
- LinkOS
- DOCS op
- living docs renderer
- Start action
- Run Forge footer action
- post-run LinkOS surface
- modern tutorial docs

## PRINCIPLE
Public docs must describe minimal Forge, not a private local Forge setup.

Use public/minimal release paths:
- forge/
- forge_entry.py
- forge/guides/
- forge/extensions/linkos/

- full-local package names
- device-specific absolute paths
- unreleased personal project surfaces

## FIRST USER FLOW
1. User opens LinkOS Home.
2. User taps Start.
3. Start copies first-time LLM starter bundle.
4. Start page says: paste this into an LLM of your choice.
5. LLM reads llm-first-time-guide and onboarding docs.
6. User runs first safe bundle.
7. Forge returns a packet.
8. Entry point renders LinkOS latest run.
9. User continues through tutorial-loop.

## STARTER BUNDLE
Public starter bundle should be:

    DOCS
    OPEN: llm-first-time-guide, onboarding
    SUGGEST: concepts, the-loop, run-packet, tutorial, tutorial-loop

## ENTRY POINT REQUIREMENT
forge_entry.py should remain simple and robust.

Target behaviour:
- read clipboard bundle
- run Forge
- copy clip_result or packet back to clipboard
- print packet as fallback
- try to render LinkOS latest run
- if LinkOS fails, do not break the run

## LINKOS PORT FINDINGS

Current LinkOS is mostly portable, but not as a blind copy.

Required import rewrite:

    forge.extensions.linkos  -> forge.extensions.linkos
    forge.registry           -> forge.registry
    forge.runtime.paths      -> forge.runtime.paths

Required path rewrite:

    forge/guides             -> forge/guides
    forge_entry.py        -> forge_entry.py

Important run-surface finding:

    forge/extensions/linkos/data/runs.py depends on forge_ui.apps.run_packet.parser and summary.

Minimal Forge does not include forge_ui, so public LinkOS needs a self-contained run reader that reads directly from:

    artifacts/runs/<stamp>/manifest.json
    artifacts/runs/<stamp>/bundle.txt
    artifacts/runs/<stamp>/logs/run_summary.txt

This is preferable for public release because LinkOS should not depend on the private/full Forge UI stack.

Public LinkOS port should include:
- render primitives
- doc pages
- docs hub
- help page
- files page
- runs page with self-contained parser
- run detail page
- safety page
- start action
- run_forge action
- doc copy/bundle copy actions
- router/state

Public LinkOS port should exclude or defer:
- bank
- command palette unless needed
- scratch page unless made public-safe
- scratch page unless made public-safe
- app-specific shortcut actions
- private workflow summaries
- unreleased personal surfaces
First implementation chunk should be:
1. render/
2. state.py
3. data/docs.py
4. pages/doc.py, docs.py, doc_missing.py, coming_soon.py
5. actions/doc_ops.py
6. router with only home/docs/doc/start routes

Then add runs/safety once the minimal run reader exists.


## SELF-CONTAINED RUN READER DESIGN

Public/minimal LinkOS must not import forge_ui.

The current full LinkOS run reader depends on:

    forge_ui.apps.run_packet.parser
    forge_ui.apps.run_packet.summary

That is not suitable for minimal Forge.

Minimal LinkOS should implement its own reader at:

    forge/extensions/linkos/data/runs.py

It should read directly from:

    artifacts/runs/<stamp>/manifest.json
    artifacts/runs/<stamp>/bundle.txt
    artifacts/runs/<stamp>/logs/run_summary.txt

Required functions:
- list_stamps(limit=80)
- latest_stamp()
- load_run(stamp=None)
- bundle_text(stamp=None)
- full_packet(run)
- recommendation(run)
- status_phrase(run)
- ai_summary(run)
- relative_time(stamp)
- neighbours(stamp)

Required run dict shape:
- stamp
- root
- bundle_sha
- results
- counts
- touched
- touched_files
- preview_count
- failed_results
- skipped_results
- inspect_count
- missing
- manifest
- bundle

Required result shape:
- index
- status
- status_emoji
- op
- op_emoji
- kind
- target
- message
- message_short
- preview
- preview_short
- file
- stdout
- stderr
- suggested
- requested
- raw

Public op groups should avoid private assumptions.

Public inspect ops:
- PREVIEW
- READ_FILE
- LIST_FILES
- LIST_TARGETS
- GREP
- HELP
- GUIDE
- DOCS

Public run ops:
- RUN_FILE
- SHORTCUT
- URL
- PIP

Public sync/share ops:
- PACK
- CLIPBOARD

Packet reconstruction should use:

    === FORGE RUN ===

not:

    === FORGE RUN ===

This keeps public LinkOS independent, portable, and aligned with minimal Forge.
