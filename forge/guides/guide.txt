# guide

## WHEN TO USE
Use when working with Forge's guide system, deciding whether to document a workflow, or teaching a future model how guides should evolve.

## CONCEPT
HELP is for concrete objects.
GUIDE is for repeatable workflows.
JOURNAL is for lived context and session continuity.
AUDIT ops are for system health.

A guide should answer:
- When do I use this workflow?
- What is the reliable pattern?
- What first bundle or first moves are useful?
- How do I validate it worked?
- What common failures should I avoid?
- What related HELP/GUIDE/JOURNAL surfaces matter?

## WHEN TO READ A GUIDE
Read a guide when:
- The goal is clear but the house workflow is not.
- You are about to do a risky or repeated task.
- You are touching Forge core.
- You are debugging a crash.
- You are adding a custom op.
- You are improving Forge health, compatibility, or docs.

## WHEN TO ADD OR UPDATE A GUIDE
Add or append to a guide when:
- A workflow succeeds and is likely to recur.
- The same mistake or failure pattern appears more than once.
- Jack explicitly says a pattern is important.
- A session reveals a better way to use Forge.
- A guide would save future models from needing the same explanation.

Do not add a guide for one-off trivia.
Do not turn every bug into process.
Prefer appending a short lesson before rewriting a guide.

## GUIDE STYLE
Keep guides:
- short
- practical
- action-shaped
- opinionated
- specific to Forge/Jacks workflow
- easy for an LLM to act on

Use sections:
- WHEN TO USE
- PATTERN
- GOOD FIRST MOVES
- VALIDATE / SMOKE TEST
- COMMON FAILURES
- RELATED

## BOOT CREEP RULE
Do not stuff every good idea into boot.
Boot teaches how to enter the system.
Specific guides teach how to work inside it.
Journal provides recent context.
Audits provide health signals.

Only add something to boot if nearly every cold session benefits from it.

## WRITE PATTERN
To create a guide:

GUIDE
ARGS: add name
<use a fenced body in the actual bundle>

To update a guide:

GUIDE
ARGS: append name
<use a fenced body in the actual bundle>

When writing guide content, avoid literal Forge body fence words inside examples if they would prematurely close the bundle body.

## AFTER A GOOD SESSION
Ask:
Was there a repeatable flow here worth saving?

If yes:
- add a new guide, or
- append a short lesson to an existing guide, and
- journal the important checkpoint if it matters for continuity.

## LESSON: GUIDE SUMMARIES

Guide list should help a cold model choose the right workflow quickly.

Every guide should ideally include a short SUMMARY near the top. If SUMMARY is missing, GUIDE list falls back to the first useful line under WHEN TO USE.
