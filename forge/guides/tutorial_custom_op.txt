# tutorial-custom-op

## SUMMARY
Learn how to create a tiny custom Forge op, refresh the registry, read its HELP page, and run it.

## WHEN TO USE
Use this after [[tutorial-docs-authoring]] or [[tutorial-ops]] when you want to understand how Forge can grow new commands.

## GOAL
Create a small custom op called TUTORIAL_HELLO.

You will learn:
- where custom ops live
- what SPEC does
- what HELP does
- how validate and execute work
- how REFRESH picks up op changes
- how HELP confirms the op is registered

## SAFETY
This tutorial creates one small file:

    forge/ops/custom/tutorial_hello.py

It does not touch Forge core parser or shortcut files.

## STEP 1 — CREATE THE CUSTOM OP
Copy and run this bundle.

    @forge-bundle tutorial-custom-op-create
    CREATE_FILE forge/ops/custom/tutorial_hello.py
    BEGIN_BODY
    # -*- coding: utf-8 -*-
    """
    tutorial_hello.py
    =================

    Tiny tutorial custom op.

    Demonstrates the minimum shape of a Forge op:
    - SPEC declares parser rules
    - HELP powers HELP TUTORIAL_HELLO
    - validate checks the parsed op
    - execute writes the result
    """

    SPEC = {
        'name': 'TUTORIAL_HELLO',
        'target_kind': 'none',
        'body_mode': 'forbidden',
        'allowed_directives': set(['NAME']),
        'required_directives': set(),
    }

    HELP = {
        'summary': 'Tiny tutorial op that prints a greeting.',
        'subject': ['No subject. Optional NAME directive changes the greeting.'],
        'directives': {
            'NAME': 'Name to greet. Defaults to Forge learner.',
        },
        'common_failures': [
            'NAME is optional.',
            'Body is forbidden.',
        ],
        'safe_usage': [
            'Use this only as a tutorial example.',
            'Run REFRESH after creating a new op module.',
        ],
        'minimal_example': [
            'TUTORIAL_HELLO',
            '',
            'TUTORIAL_HELLO',
            'NAME: Forge user',
        ],
        'related_ops': ['HELP', 'LIST_OPS', 'REFRESH'],
    }

    HINTS = {
        'refresh': 'Run REFRESH after creating a new custom op.',
    }


    def validate(parsed_op):
        """No validation needed for this tutorial op."""
        return []


    def execute(ctx, parsed_op, result):
        """Write a greeting into the run packet preview."""
        name = (parsed_op.directives.get('NAME') or 'Forge learner').strip()
        result['status'] = 'APPLIED'
        result['message'] = 'greeted %s' % name
        result['preview'] = 'Hello, %s. Your custom op ran.' % name
    END_BODY
    @end-forge-bundle

## EXPECT
The packet should show:

    APPLIED | CREATE_FILE | forge/ops/custom/tutorial_hello.py

The op file now exists, but Forge may not know about it until you refresh.

## STEP 2 — REFRESH AND DISCOVER THE OP
Run REFRESH, then list custom ops and read HELP.

    @forge-bundle tutorial-custom-op-refresh
    REFRESH

    LIST_OPS custom

    HELP TUTORIAL_HELLO
    @end-forge-bundle

## EXPECT
The packet should show:
- REFRESH applied
- LIST_OPS custom includes TUTORIAL_HELLO
- HELP TUTORIAL_HELLO shows the help metadata

If HELP cannot find the op, restart Pythonista once and try again. New op discovery can sometimes need a restart.

## STEP 3 — RUN THE CUSTOM OP
Now run the op.

    @forge-bundle tutorial-custom-op-run
    TUTORIAL_HELLO

    TUTORIAL_HELLO
    NAME: Forge user
    @end-forge-bundle

## EXPECT
The packet should show two APPLIED ops.

The preview should include greetings.

## STEP 4 — INSPECT THE OP FILE
Preview the op you created.

    @forge-bundle tutorial-custom-op-preview
    PREVIEW forge/ops/custom/tutorial_hello.py
    LINES: 1-120

    LIST_TARGETS forge/ops/custom/tutorial_hello.py
    @end-forge-bundle

## EXPECT
The packet should show the source code and patchable Python targets.

Notice:
- SPEC
- HELP
- HINTS
- validate
- execute

That is the basic shape of a custom op.

## STEP 5 — CLEAN UP
Delete the tutorial op when finished.

    @forge-bundle tutorial-custom-op-cleanup
    DELETE_FILE forge/ops/custom/tutorial_hello.py

    REFRESH
    @end-forge-bundle

## EXPECT
The packet should delete the file and refresh the registry.

If LIST_OPS still shows the op until restart, that is module cache behaviour. Restart Pythonista if needed.

## WHAT YOU LEARNED
You created a new Forge command.

A custom op needs:
- SPEC for parser rules
- HELP for reference
- optional HINTS for failure guidance
- validate for pre-run checks
- execute for behaviour

## COMMON MISTAKES
- Forgetting REFRESH after creating a new op.
- Missing SPEC.
- Using a directive that is not in allowed_directives.
- Forgetting to set result status.
- Putting real project side effects into a tutorial op.
- Touching core files before understanding custom ops.
